## 1. Project Overview

### 1.1 Vision
An autonomous research orchestrator that investigates a user-defined question through an iterative loop:

```
Question → Search → Knowledge Fusion → Self-Correction → Report
```

Unlike single-shot AI search tools, this system:

1. Understands what it doesn't know (gap detection).
2. Decides what to research next (JEV decision engine).
3. Extracts structured claims (subject–predicate–object + confidence).
4. Detects contradictions and triggers verification searches.
5. Verifies evidence quality and stops when sufficient.
6. Produces an evidence-backed report with full source attribution.

### 1.2 Core Concepts

| Term | Meaning in this codebase |
|------|--------------------------|
| **Research Session** | One investigation: `ResearchSession` row with question, depth, status (`initializing`/`running`/`completed`/`error`/`stopped`), iteration counter, `report_data` JSON. Created by `SessionManager.create_session()`, driven by `ResearchOrchestrator(session_id)`. |
| **IKF (Iterative Knowledge Fusion)** | `app/services/knowledge_fusion.py → KnowledgeFusion.fuse_claims()`. Turns claims into `KnowledgeNode` + `KnowledgeEdge` rows. Resolves entities to a canonical name (`OpenAI Inc.` → `OpenAI`), takes edge strength from evidence strength when the caller scored the claims (falling back to confidence 0.9/0.7/0.5), and records per-edge provenance in `edge_provenances`. |
| **IKF 2.0 knowledge layer** | `app/services/ikf/` — `entity_resolution`, `temporal`, `claim_versioning`, `provenance`, `evidence` (all pure) + `service` (the only DB-aware module). Provides evidence strength, temporal versions vs real conflicts, and provenance. |
| **JEV (Judgment Evaluation Vector)** | `app/services/decision_engine.py → DecisionEngine.select_action()`. Hardcoded heuristic policy (V1, RL-ready logging via `Decision` + `compute_reward_signal()`). Actions: `SEARCH`, `VERIFY`, `EXPAND_QUERY`, `STOP` (`EXTRACT`/`FUSE` defined but not selected by policy). |
| **Claim** | Atomic factual proposition extracted by LLM: `claim`, `subject`, `predicate`, `object`, `confidence` (high/medium/low), linked to sources via `ClaimSource` (`supports`/`refutes`/`neutral`). |
| **Contradiction** | Pair of conflicting claims confirmed by Tier-3 LLM, with `severity` (low/medium/high) and `resolution_note` (explanation). |
| **Information Gain** | Novelty metric per iteration (`services/metrics.py → compute_information_gain()`). Drives plateau / diminishing-returns stopping rules. |
| **Coverage** | Completeness estimate (`compute_coverage_estimate()`) from claims/sources/nodes vs depth targets. |

### 1.3 Current Implementation Status

## 4. Backend Deep Dive

### 4.1 App entrypoint — `app/main.py`
- `lifespan`: `init_db()` → `ws_manager.set_event_recorder(record_session_event)` → `SessionManager.reconcile_interrupted_sessions()` (marks `running` sessions from a crashed process as `error`) → `cache_manager.initialize()` (warn-only on failure).
- Middleware order: `RequestContextMiddleware` then `CORSMiddleware` (origins from `settings.CORS_ORIGINS`).
- Routers: `research`, `sessions`, `knowledge`, `evidence`, `reports`.
- `GET /health` (liveness, no auth): `{status, environment, timestamp, version}`.
- `GET /health/ready` (no auth, DB probe): 200 `{status: ready, database: ok}` or 503 `{status: unavailable}`.

### 4.3 API layer

**Auth & shared deps (`api/dependencies.py`, `api/errors.py`, `api/rate_limit.py`, `api/middleware.py`)**
- Every `/api/*` route requires `X-API-Key` (dev default tolerated). WebSocket uses `?api_key=` query param and is rejected pre-accept (`WS_1008_POLICY_VIOLATION`) on mismatch.
- Standard error envelope `{"error": {"message", ...}}` — frontend `apiFetch` surfaces `error.message`.
- `RequestContextMiddleware` adds correlation IDs, timing, access logs.

**Routes**

`api/routes/research.py` (prefix `/api/research`):
- `POST /api/research/start` (201) — validates question (`validate_question` + Pydantic ≥10 chars, ≥3 words), `SessionManager.create_session()`, `launch_research_task()`, returns `ResearchSessionResponse` with `max_iterations` + `estimated_time_seconds` from depth profile.
- `GET /api/research/{session_id}` — session + `total_sources`/`total_claims` stats.
- `POST /api/research/{session_id}/stop` — marks stopped, broadcasts `{type: stopped, by: user}`.
- `GET /api/research/{session_id}/events?after_seq=&limit=` (max 2000) — durable replay log (`SessionEventsResponse`).
- `WS /api/research/ws/{session_id}?api_key=` — live stream; handles `ping→pong`; multi-client fan-out.

`api/routes/sessions.py` (prefix `/api/sessions`):
- `GET /api/sessions?skip=&limit=` (1–100, default 20) — paginated summaries with live counts.
- `DELETE /api/sessions/{session_id}` (204) — cascade delete.

`api/routes/knowledge.py`: `GET /api/research/{session_id}/knowledge` → `{session_id, nodes:[{id,label,entity_type,description}], edges:[{id,from_node,to_node,label,strength}], total_nodes, total_edges}` (vis-network ready).

`api/routes/evidence.py`:
- `GET /api/research/{session_id}/evidence` → `{session_id, total_claims, claims:[{..., sources:[{source_id,url,title,credibility_score,support_type,confidence}]}]}`.
- `GET /api/research/{session_id}/contradictions` → `ContradictionItem[]` with both claim texts + severity + resolved + note.

`api/routes/reports.py`: `GET /api/research/{session_id}/report` — returns stored `report_data` if present, else generates on demand and persists.

**Schemas (`api/schemas/`)**
- `research.py`: `ResearchQuestionInput` (question 10–2000 chars, depth `shallow|standard|deep` default `standard`, domain, geographic_scope `global`, time_range, max_time 1–10 default 5, min_sources 3–50 default 10, output_format `report|bullet_points|briefing`), `ResearchSessionResponse`, `StopSessionResponse`, `SessionEventItem/Response`.
- `session.py`: `SessionSummary`, `SessionListResponse`.
- `claim.py`: `ClaimModel`, `ClaimSourceLink`, `ContradictionItem`, `EvidenceResponse`.
- `knowledge.py`: `KnowledgeNodeModel`, `KnowledgeEdgeModel`, `KnowledgeGraphResponse`.
- `source.py`: source models.

### 4.4 Services (research loop)

**`services/research_orchestrator.py`** — the loop. `launch_research_task(session_id)` dedups concurrent runs per session and tracks `asyncio.Task`s. `ResearchOrchestrator(session_id).run()` wraps `_run()` and always `llm_router.release_session()`.
`_run()` per iteration:
1. Abort check (status `stopped`/`error` → broadcast `stopped`) + `increment_iteration()` + time-budget check.
2. Broadcast `search_started {iteration, query}` → `SearchAgent.search(query, db, max_results=8)` (max_queries = `min_sources_required*3`) → broadcast `sources_found {count, total_sources}`.
3. If new sources: broadcast `extraction_started` → `ClaimExtractor.extract_from_sources()` → broadcast `claims_extracted {count, total_claims}`.
4. If new claims: `KnowledgeFusion.fuse_claims()` → broadcast `knowledge_updated {nodes, edges}`.
5. Contradiction stage (skipped with warning if time budget spent): `detect_contradictions()` + `identify_knowledge_gaps()` → broadcast `contradiction_detected` if any.
6. Metrics: `compute_information_gain()` + plateau counter + `compute_coverage_estimate()` + contradiction-signature check → `KnowledgeState` → `DecisionEngine.select_action()` → `record_decision()` → broadcast `decision_made {action, reasoning, coverage (+stop_reason)}` + `iteration_complete {iteration, information_gain, coverage, llm_calls, budget_calls, context_chars, context_budget_chars}`.
7. `STOP` → break; `VERIFY` remembers signature; next query = gap[0] (`EXPAND_QUERY`) / `evidence for or against: <claim>` (`VERIFY`) / `<question> key findings and analysis` (default); `await asyncio.sleep(1)`.
8. Exceptions: `SessionBudgetExceededError` → graceful stop reason + continue to report; other → `_mark_failed()` (status `error` + `error` broadcast, no report).
9. `ReportGenerator.generate_report()` → broadcast `completed {report_ready, stop_reason, total_claims, total_sources, budget telemetry}`.

**`services/session_manager.py`** — `create_session()` (validates depth via `get_depth_profile`, sets `initializing`), `stop_session()`, `get_session_stats()` (counts), `reconcile_interrupted_sessions()` (startup recovery).

**`services/search_agent.py`** — `SearchAgent(session_id, max_queries)`; `search()` enforces quota (`RateLimitExceededError`), calls `TavilyClient`, dedups by URL (`get_existing_urls`), cleans HTML (`clean_html_content`), hashes content, scores credibility, parses `published_date`, persists via `SourceRepository.create()`.
`estimate_source_credibility(url)`: exact/subdomain match on `HIGH_AUTHORITY_DOMAINS` (arxiv/nature/science/nih/ieee/acm 0.92–0.95, reuters/bloomberg 0.85, bbc 0.82, wiki 0.75) and `LOW_AUTHORITY_DOMAINS` (reddit 0.35, twitter/x 0.30, quora 0.40, medium 0.50); TLD fallback `.edu/.gov/.mil` 0.90, `.org` 0.70, default 0.60.

**`services/claim_extractor.py`** — `ClaimExtractor(session_id).extract_from_sources(sources, question, db)`: skips content <50 chars, truncates to 4000 chars, Tier-2 (`TaskType.EXTRACT`, temp 0.1) prompt for 2–6 atomic claims, strips markdown fences, regex-extracts JSON, 3 attempts, validates length ≥10 and confidence enum, persists claim + `link_source(supports, credibility)` .

**`services/knowledge_fusion.py`** — `fuse_claims(claims, db, resolver=None, evidence=None) → (new_nodes, new_edges)`: resolves subject and object through the session-scoped `EntityResolver`, skips subjects <2 or >80 chars, creates subject (`entity`) + object (`concept`, 2–80 chars) nodes via `get_or_create_node`, dedups edges by `(src, dst, predicate.lower())`. Edge strength is the claim's evidence strength when supplied; a later, better-evidenced restatement upgrades the edge and a weaker one never downgrades it. Source refs are loaded for all claims in **one** query (`ClaimRepository.get_links_for_claims`) because the loop hands fusion claims whose session has already closed. Provenance is recorded for *every* supporting claim and merged, not just for the one that created the edge. Returns counts used for info-gain.

**`services/contradiction_detector.py`** — `detect_contradictions(db, max_comparisons=15)`: candidate pairs sharing subject or predicate (case-insensitive), fallback to recent 5×6 pairs, skips already-judged pairs, Tier-3 (`CONTRADICTION`, temp 0.1) verification prompt → `{contradicts, severity, explanation}` → persists. `identify_knowledge_gaps(db, question)`: top-15 claims summary + Tier-3 (`REASON`, temp 0.2) → JSON array of 1–3 follow-up search queries.

**`services/decision_engine.py`** — JEV policy (see §10). `record_decision()` persists snapshot (`asdict(state)`), available actions, reasoning, `compute_reward_signal()`.

**`services/report_generator.py`** — `generate_report(db)`: loads session/sources/claims/contradictions/graph; builds numbered `citations` + `evidence_table` (claim + S/P/O + confidence + citation numbers); Tier-3 (`REPORT`, temp 0.2) synthesis prompt (top-25 claims) → `{executive_summary, key_findings[3–6], unknowns[2–4]}` with `synthesis_mode: llm|fallback` provenance; rule-based fallback uses first claims; persists via `save_report()` and returns dict with `metadata {totals, coverage, synthesis, generated_at}`.

**`services/depth_config.py`** — single source of truth (see §9).

**`services/metrics.py`** — `compute_coverage_estimate()`, `compute_information_gain()`, `compute_reward_signal()` (`info_gain + credibility*confidence − 5×contradictions − 2×duplicates − 0.1` family).

**`services/event_recorder.py`** — `record_session_event()` persists every WS broadcast as `SessionEvent(seq, event_type, iteration, payload)` for replay.

### 4.5 Integrations

- `tavily_client.py`: `TavilyClient.search(query, max_results)` → `[{url,title,content,published_date,score}]`; tenacity backoff on 429; returns `[]` (not crash) when key missing or API fails — loop continues with zero new sources.
- `llm_router.py`: `TaskType` = `classify|extract|summarize|contradiction|reason|report`. `CLASSIFY` → Tier 1 Ollama if `is_available()` else Tier 2; `EXTRACT|SUMMARIZE` → Tier 2 (Gemini Flash) fallback Tier 3 Groq; rest → Tier 3 Groq if key else Tier 2. Global semaphore (`LLM_MAX_CONCURRENT_CALLS`) + per-session semaphore + call/context budgets; `_generate_with_retry` retries **only** `RateLimitExceededError` (2s exponential, `LLM_RETRY_ATTEMPTS`); `usage()`/`release_session()`/`reset()` for telemetry/cleanup. Actual models in code: `gemini-3.8-flash`, Groq `openai/gpt-oss-120b`.
- `gemini_client.py` / `groq_client.py` / `ollama_client.py`: thin async wrappers with rate-limit mapping.
- `cache_manager.py`: Redis with in-memory fallback.
- `error_handlers.py`: retry/circuit-breaker helpers.

### 4.6 Database & utils & WS

- `database/session.py`: async engine/session factory + `init_db()` (create-all; Alembic available for Postgres).
- `database/repository.py`: `SessionRepository` (get/create/update_status/increment_iteration/save_report/list/delete/stats), `SourceRepository` (create/get_by_session/get_existing_urls), `ClaimRepository` (create/link_source/get_by_session), `KnowledgeRepository` (get_or_create_node/add_edge/get_graph), `ContradictionRepository`, `DecisionRepository` (log_decision), `SessionEventRepository` (append/list_events). No raw SQL in services.
- `database/migrations/versions/001_initial_schema.py` + `env.py`: initial schema (mirrors `models.py`).
- `utils/validators.py`: `validate_question()` (non-empty, ≥10 chars); `utils/parsers.py`: `clean_html_content()`, `truncate_for_llm()`; `utils/helpers.py`: `compute_content_hash()`, `compute_url_domain()`, UUID/time helpers; `utils/logger.py`: structured logger with session context.
- `ws/managers.py`: `ws_manager` keeps **sets** of sockets per session, `connect/disconnect`, `broadcast()` fans out and first persists via recorder hook; dead sockets pruned.

## 5. Frontend Deep Dive

### 5.1 Shell — `app/page.tsx` + `app/layout.tsx`
Single-page app with 4 views (`home|research|settings|about`, `VIEW_TITLES`), `Sidebar` nav, header (title + a single **top-right** menu button), footer. State: `session`, `refreshTrigger` (refreshes history), `navOpen` (narrow-viewport drawer) and `navCollapsed` (desktop panel). The menu button is rendered only while the menu is hidden, so it always reveals it and never appears inert. `.app-shell` carries `nav-collapsed` / `nav-drawer-open`, and `matchMedia("(max-width: 1024px)")` is checked at click time to pick which state to change. Desktop collapse is a plain `display: none` on `.sidebar`; the narrow-viewport drawer slides with `transform` and uses `visibility: hidden` while closed so it stays out of the tab order. `useResearchSocket()` provides `messages|activity|isConnected|connect|disconnect`. Starting/selecting a session connects the socket only for `running/initializing`; finished sessions use event replay. `research` view with null session shows empty-state card.

### 5.2 Research components (`components/research/`)
- `ResearchForm.tsx`: question textarea + depth selector + constraints (min sources, max time, scope) → `startResearch()` → `onStart(session)`.
- `ResearchDashboard.tsx`: orchestrates tabs/panels for live run + finished report; polls `getSession()` as WS fallback; renders progress, activity, graph, evidence, contradictions, report; stop/reset/export actions.
- `ReportView.tsx`: executive summary card + key findings + evidence table (sortable by confidence) + contradictions + unknowns + numbered citations with credibility badges + JSON/PDF export (`lib/pdf.ts`).
- `KnowledgeGraphView.tsx`: vis-network (physics, pan/zoom, labels); caps large graphs for performance.
- `SessionHistory.tsx` + `DashboardStats.tsx`: past sessions list (question/status/date/duration/counts), select/delete, aggregate stats.

## 6. Data Model (actual `database/models.py`)

10 tables, string UUID PKs, timezone-aware timestamps, cascade deletes from `research_sessions`, `JSON` (JSONB on Postgres) for snapshots/reports:

- `users(id, api_key UNIQUE, created_at)` → `sessions`.

- `claims(id, session_id CASCADE, claim TEXT, subject(255) indexed, predicate(255) indexed, object TEXT NULL, confidence default medium, status default active, created_at)` + composite index `(subject, predicate)`.
- `claim_sources(id, claim_id CASCADE, source_id CASCADE, support_type default supports, confidence default 0.8)`.
- `knowledge_nodes(id, session_id CASCADE, entity TEXT, entity_type default concept, description NULL, created_at)`.

## 7. Research Lifecycle (as coded)

```
POST /start → validate → create session (initializing) → launch task ─┐
GET /{id} polls status/iterations/counts                              │
WS /ws/{id} streams live events; GET /events replays history          │
                                                                      ▼
Loop iteration (max per depth profile):
  increment_iteration → time check → search_started
  → Tavily search (dedup+score+persist) → sources_found
  → [if new sources] extraction_started → LLM extract+link → claims_extracted
  → [if new claims] IKF fuse → knowledge_updated
  → IKF 2.0 index (resolution + evidence + versioning) → ikf_updated
  → [if time left] Tier-3 contradiction verify + gap queries → contradiction_detected?
  → metrics + JEV select_action + record_decision → decision_made + iteration_complete
  → STOP? break : next query (gap / verify-claim-text / default) → sleep 1s
→ ReportGenerator → persist report_data → completed {report_ready, stop_reason, totals, budgets}
STOP endpoint / timeout / budget-exceed / error → stopped/error (+ partial or on-demand report)
```

Stopping triggers (JEV + orchestrator): time limit, max iterations, already-verified contradictions fall-through, coverage <0.65 → SEARCH, zero-yield stagnation (iteration ≥2, 0 new sources+claims+nodes) → STOP, convergence plateau (iteration ≥3, two consecutive gains <0.15, coverage ≥0.75) → STOP, diminishing returns (≥3 iters, ≥3 plateau iters, gain <0.10, coverage ≥0.55, Δ<0.03) → STOP, gaps → EXPAND_QUERY, else SEARCH; budget-exceed → graceful stop + report.

## 10. JEV Decision Policy (actual thresholds)

Constants: `NOVELTY_PLATEAU_GAIN=0.15`, `DIMINISHING_GAIN=0.10`, `COVERAGE_FLOOR=0.65`, `CONVERGENCE_COVERAGE=0.75`, `WEAK_PLATEAU_COVERAGE=0.55`, `MARGINAL_COVERAGE_DELTA=0.03`, `PLATEAU_PATIENCE=3`.

Order: time exceeded → STOP; iteration ≥ max → STOP; new unresolved contradictions (and `iteration < max−1`) → VERIFY; coverage <0.65 → SEARCH; zero-yield stagnation (iter ≥2) → STOP; convergence plateau (iter ≥3) → STOP; diminishing returns (iter ≥3) → STOP; gaps remain → EXPAND_QUERY; else SEARCH (or STOP if at cap). Each decision logged with reward for future RL.

## 11. LLM Router Summary

`TaskType`: `classify` (Tier 1 Ollama → fallback Gemini), `extract|summarize` (Tier 2 Gemini → fallback Groq), `contradiction|reason|report` (Tier 3 Groq if key else Gemini → fallback Gemini). Concurrency: global semaphore + per-session semaphore; budgets per session (calls + context chars); retries only on rate limits with exponential backoff; `usage(session_id)` telemetry on every `iteration_complete`/`completed` event; `release_session()` prevents registry growth.

Prompt highlights: extraction demands JSON-only atomic claims (2–6/source, confidence rubric); contradiction verification returns `{contradicts, severity, explanation}`; gap finder returns 1–3 query strings; report synthesis returns `{executive_summary, key_findings, unknowns}` with fallback provenance flag.

## 14. Troubleshooting

| Symptom | Likely cause / fix |
|---------|--------------------|
| Session has 0 sources | `TAVILY_API_KEY` missing/invalid — check backend logs; search returns `[]` by design. |
| Claims empty / fallback synthesis | LLM keys missing or rate-limited — router warnings in logs; `metadata.synthesis: fallback` in report. |
| Loop runs to max iterations | Gaps keep generating queries or coverage never hits thresholds — expected; check `decision_made` reasoning events. |
| WS not connecting | `NEXT_PUBLIC_WS_URL` / `NEXT_PUBLIC_API_KEY` mismatch; server rejects with 1008 before accept. |
| Finished session shows empty activity | Use `GET /events` replay (automatic in UI); old DBs pre-migration need `init_db`/Alembic. |
| DB locked / stale running | Restart backend — `reconcile_interrupted_sessions()` marks orphans `error`. |

## 16. V2 — Offline Learning, Shadow Policy & Long-Term Memory (shipped 2026-10-02)

### 16.1 What it is

A dependency-free offline learning layer beside the V1 loop. **JEV still decides
everything live**; the layer records every step as a transition, logs what the
offline policy *would* have done (shadow mode — stored, broadcast, never executed),
builds a validated JSONL dataset, trains a lightweight tabular policy from it, and
compares RL vs JEV on historical trajectories. Long-term memory (2.1/2.12) recalls
prior knowledge at session start, promotes durable findings at the end, and keeps
conflicting readings side-by-side instead of overwriting.

### 16.2 Backend surface

| Endpoint | Purpose |
|---|---|
| `GET /api/research/{id}/trajectory` | Recorded `state → action → reward → next_state` steps, totals, policy mix |
| `GET /api/research/{id}/decisions` | Decision inspector join: state, available actions, JEV choice + reasoning, RL choice, actual action, reward + explanation |
| `GET /api/research/{id}/decisions/raw` | Raw decision log rows |
| `GET /api/research/{id}/predictions` | Shadow predictions + agreement/disagreement totals |
| `GET /api/research/{id}/state` | Formal `ResearchState` (hash, size, discretised features, latest prediction) |
| `GET /api/evaluation/dataset` · `/dataset/stats` · `/dataset/export` | Validated dataset, statistics, JSONL download |
| `POST /api/evaluation/dataset/backfill` | Reconstruct transitions from pre-V2 history (completed sessions without transitions) |
| `POST /api/evaluation/dataset/build` | Build (optionally `train=true` → fit + store a policy; `backfill=true` runs history backfill first) |
| `POST /api/evaluation/run` | Offline JEV-vs-RL evaluation (`policy`, `baseline`, `max_steps`, `session_ids`) |
| `GET /api/evaluation/results[/{id}]` · `/policies` · `POST /policies/train` · `POST /policies/{id}/activate` · `/reward-formula` | Run history, policy management, self-describing reward formula |
| `GET /api/memory/search` · `/session/{id}` · `/conflicts` · `POST /promote` | Memory retrieval, per-session provenance, versioned conflicts, promotion |

**History backfill** — V1 sessions predate `research_transitions`, so
`rl/service.backfill_history()` reconstructs transitions from stored history. V1
decision semantics it encodes: the run starts with an unconditional SEARCH whose
outcome is the state *before* decision 1; decision *k* is logged at the end of
iteration *k* and selects the action executed in iteration *k+1*; the terminal
STOP executes nothing. Backfill is idempotent (completed sessions without
transitions only), per-session fault-isolated, flags reconstructed steps in the
observation (`backfilled`, `reconstructed_from`), and was verified against the
development DB: 8 completed sessions → 31 clean transitions, 0 validator drops.

New tables (migration `002_learning_layer`): `research_transitions`,
`rl_policies`, `rl_predictions`, `evaluation_runs`, `evaluation_results`. New WS
events: `transition_recorded`, `rl_shadow`, `memory_recalled`, `memory_updated`.
Config flags: `RL_TRAJECTORY_ENABLED`, `RL_SHADOW_ENABLED`, `RL_POLICY_MIN_SAMPLES`,
`RL_POLICY_SHRINKAGE`, `RL_DATASET_MAX_TRANSITIONS`.

### 16.3 Frontend surface

| View / tab | File | Shows |
|---|---|---|
| State inspector (tab) | `lib/state-inspector.tsx` | Formal state grid, unresolved gaps, budget pressure, reward breakdown (credit/debit rows), latest shadow prediction |
| Decisions (tab) | `components/research/DecisionInspector.tsx` | Per-iteration chain: state → available actions → JEV decision → RL recommendation → actual action → reward; list + detail modes |
| RL evaluation (view) | `components/research/EvaluationDashboard.tsx` | Dataset stats, action/policy distributions, policy list + activate, run wizard, JEV-vs-RL metric cards, per-session + per-action tables, run history |
| Long-term memory (view) | `components/research/MemoryPanel.tsx` | All items / semantic search / versioned conflicts with provenance / per-session contributions + re-promote |
| Replay | `lib/timeline.ts`, `lib/useResearchSocket.ts` | The four new V2 events are persisted, replayed and humanised in the activity log |

### 16.4 Safety properties

- Every recorder/shadow/memory failure is caught, logged and swallowed — an RL or
  memory outage degrades to plain V1 behaviour, never breaks a run.
- Policy activation affects only shadow predictions and offline evaluation;
  `POST /policies/{id}/activate` cannot touch the live loop.
- No heavy RL dependencies (no PyTorch/SB3); the `ActionPolicy` protocol is the
  future seam.
- API-key auth, rate limiting and the error envelope match V1 conventions.
